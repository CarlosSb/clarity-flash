# Completar Migração Fiber v3 e Limpeza de Código

## Objetivo
Finalizar a migração completa para Fiber v3, corrigir issues identificados na revisão de código, remover código inutilizado do net/http, e validar a migração com testes e benchmarks.

## Estado Atual da Migração
- ✅ Go 1.25+ configurado
- ✅ Fiber v3 instalado
- ✅ App Fiber básico criado
- ✅ Roteamento convertido
- ✅ Handlers principais convertidos
- ✅ Middleware convertido
- ✅ Servidor inicia e responde
- ⚠️ Issues na revisão de código
- ❌ Código legado não removido
- ❌ Testes de integração não atualizados
- ❌ Benchmarks de performance não executados
- ❌ Profiling de memória não feito

## Issues Identificados na Revisão
1. **FileHeader incorreto**: Em `session.go` FiberUpload, construção manual de `*multipart.FileHeader` pode estar incompleta
2. **Código comentado**: `routes.go` tem handler comentado
3. **Handler legado inutilizado**: `health.go` tem `LegacyHealthHandler` não usado

## Plano de Continuação

### Fase 1: Correção de Issues Críticas (1-2 horas)
1. **Corrigir FileHeader em FiberUpload**:
   - Verificar se `processor.Process` precisa de campos adicionais do FileHeader
   - Se necessário, ajustar construção ou passar `nil` se suportado

2. **Remover código comentado**:
   - Remover linha comentada em `routes.go`
   - Remover `LegacyHealthHandler` em `health.go`

3. **Verificar outros handlers**:
   - Garantir que todos os handlers convertidos estão corretos
   - Verificar se há referências restantes ao net/http

### Fase 2: Limpeza Completa do Código Legado (2-3 horas)
1. **Remover imports net/http**:
   - Remover `net/http` de arquivos que não precisam mais
   - Atualizar imports conforme necessário

2. **Remover handlers legados**:
   - Remover versões `(w, r)` dos handlers se não são mais usados
   - Manter apenas versões Fiber

3. **Atualizar middleware**:
   - Remover funções net/http do middleware
   - Manter apenas versões Fiber

4. **Limpar routes.go**:
   - Remover ou reescrever routes.go para Fiber
   - Ou manter como documentação se útil

### Fase 3: Testes e Validação (3-4 horas)
1. **Testes unitários**:
   - Criar testes básicos para handlers Fiber
   - Testar middleware JWT

2. **Testes de integração**:
   - Reescrever testes usando Fiber test utilities
   - Testar endpoints principais: health, auth, upload

3. **Testes funcionais**:
   - Testar fluxo completo: register → login → upload → get session
   - Verificar exports CSV/TXT

### Fase 4: Performance e Otimização (2-3 horas)
1. **Benchmarks de performance**:
   - Usar `wrk` ou `vegeta` para testar throughput
   - Comparar com baseline se possível

2. **Profiling de memória**:
   - Usar `pprof` para verificar uso de memória
   - Comparar alocações

3. **Testes de carga**:
   - Simular múltiplas conexões simultâneas
   - Verificar comportamento sob stress

### Fase 5: Deployment e Rollback (1-2 horas)
1. **Build e configuração**:
   - Verificar build em diferentes ambientes
   - Testar configurações de produção

2. **Plano de rollback**:
   - Manter branch com versão net/http
   - Documentar steps de rollback se necessário

3. **Monitoramento**:
   - Setup básico de métricas
   - Logging adequado

## Critérios de Sucesso
- ✅ Servidor inicia sem erros
- ✅ Todos os endpoints funcionam
- ✅ Testes passam (unitários + integração)
- ✅ Performance igual ou melhor que net/http
- ✅ Memória estável sob carga
- ✅ Código limpo, sem legado

## Riscos e Mitigações
- **Regressão funcional**: Testes abrangentes mitigam
- **Performance pior**: Benchmarks identificam issues
- **Incompatibilidade WebSocket**: Testar se usado no futuro
- **Issues não descobertos**: Revisão de código adicional
